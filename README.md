# 어디뒀지? — Phase 1 완성본

모의 데이터로 물품과 보관 위치를 관리하는 한국어 웹앱입니다.
React + TypeScript + Vite + Tailwind CSS를 사용합니다.

## 중요한 동작

새로고침하거나 탭을 닫으면 모든 변경 내용과 사진이 초기화됩니다.
데이터는 브라우저 메모리에만 보관됩니다. 다른 탭·PC·Android와 공유되지 않습니다.
실제 개인정보 대신 예제 데이터를 사용해 주세요.

Gemini, Supabase 로그인·동기화·초대·권한·RLS·사진 저장소와 배포는 이후 단계입니다.
사진은 서버로 업로드하지 않으며 모의 AI도 실제 인식이나 API 호출을 하지 않습니다.

## VS Code에서 실행

검증한 환경은 Windows, Node.js 24.21.0, npm 11.19.0입니다.
자동 테스트는 TypeScript를 직접 실행하는 Node.js 24 이상을 사용해 주세요.

1. VS Code에서 `파일 → 폴더 열기`를 선택합니다.
2. 이 README.md와 package.json이 들어 있는 폴더를 엽니다.
3. `터미널 → 새 터미널`을 선택합니다.
4. 처음에는 아래 명령을 한 줄씩 실행합니다.

```powershell
npm.cmd ci
npm.cmd run dev
```

5. 브라우저에서 터미널에 표시되는 Local 주소를 엽니다.
6. 종료하려면 서버가 실행 중인 터미널에서 Ctrl+C를 누릅니다.

다음 실행부터는 `npm.cmd run dev`만 입력하면 됩니다.
PowerShell의 실행 정책 문제를 피하도록 `npm` 대신 `npm.cmd`로 안내합니다.
`npm.cmd ci`는 package-lock.json에 지정된 의존성을 설치하므로 처음에 인터넷이 필요합니다.
전달 폴더에는 node_modules를 포함하지 않습니다.

### 명령을 찾을 수 없을 때

Node.js 설치 후 VS Code를 완전히 종료하고 다시 엽니다.
5173 포트가 사용 중이면 이미 실행된 개발 서버를 종료한 다음 다시 실행하세요.
개발 서버는 PC 내부 접속만 허용합니다. Android 실기기 접속은 아직 구성하지 않았습니다.

## 사용 방법

### 물품 등록·검색·수정·이동·삭제

- `물품 등록`에서 이름·수량·위치를 입력합니다. 사진·태그·메모는 선택입니다.
- 이름·태그·메모에 포함된 글자로 검색합니다. 한글 초성 검색과 오타 보정은 지원하지 않습니다.
- PC에서는 왼쪽 보관 위치를, 모바일에서는 검색창 아래 위치 선택을 사용합니다.
- 상위 위치를 선택하면 하위 위치의 물품도 함께 표시됩니다.
- 물품 카드를 누르면 상세 화면에서 수정·위치 이동·삭제할 수 있습니다.
- 이동·수정은 저장을 눌러야 반영됩니다. 취소·닫기·Escape는 변경을 저장하지 않습니다.
- 삭제는 대상 이름을 확인하는 별도 화면에서 확정합니다.
- 이름이 같은 물품을 여러 개 등록할 수 있습니다.
- 물품 수량은 1~999,999 사이의 정수입니다. 한 기록은 한 위치에 속합니다.
- 같은 물품을 여러 곳에 나눠 보관한다면 각각 별도 기록으로 등록하세요.
- 검색·필터가 걸려 있으면 새 물품이 목록에 안 보일 수 있으니 검색과 위치 선택을 초기화하세요.

### 보관 위치 관리

- `위치 관리`에서 최상위 공간과 하위 위치를 추가합니다.
- 종류는 공간·방·가구·서랍·기타이며 자유롭게 중첩할 수 있습니다.
- 기존 위치의 `수정`에서 이름·상위 위치·종류를 바꿀 수 있습니다.
- 위치를 옮기면 하위 위치와 물품 경로도 함께 바뀝니다.
- 자기 자신이나 하위 위치 안으로 이동하는 것은 차단됩니다.
- 같은 상위 위치에는 같은 이름을 중복 등록할 수 없습니다.
- 하위 위치 또는 물품이 남아 있는 위치는 삭제할 수 없습니다.

### 사진과 모의 AI

- `사진 선택` 또는 `사진 촬영`으로 파일을 선택합니다.
- JPEG·PNG·WebP, 최대 5MB, 최대 4천만 화소를 허용합니다.
- 손상된 파일이나 지원하지 않는 형식은 안내 메시지를 표시합니다.
- 촬영 입력은 기기에 따라 카메라 대신 파일 선택기로 열릴 수 있습니다.
- HEIC 파일은 JPEG 등 지원 형식으로 변환한 뒤 선택하세요.
- 사진은 이 브라우저의 메모리에만 유지됩니다.
- 사진이 있으면 `모의 분석`을 눌러 정해진 후보를 볼 수 있습니다.
- 후보를 선택하면 이름·태그에 반영되며, 직접 고친 뒤 저장할 수 있습니다.
- 후보는 선택한 사진과 무관합니다. 실제 물체 인식 결과가 아닙니다.

## 코드 읽는 순서

```text
src/
├─ App.tsx                         전체 화면과 기능 연결
├─ components/ui/                  공통 대화상자·위치 선택
├─ features/items/ItemForm.tsx      물품 입력·사진·모의 AI
├─ features/locations/             위치 트리·위치 관리
├─ domain/                         데이터 형태와 입력 검증
├─ repositories/interfaces.ts      데이터 저장소의 공통 약속
├─ repositories/memory/            모의 데이터 처리
├─ mocks/seedData.ts                예제 위치 12곳·물품 15종
├─ lib/                            위치 경로·사진 검증
└─ index.css                       반응형 화면 스타일
```

예제 물품을 바꾸려면 `src/mocks/seedData.ts`, 화면 문구를 바꾸려면 `src/App.tsx`를 열어 보세요.
Ctrl+S로 저장하면 개발 화면에 반영됩니다. 개발 중 코드 변경으로 데모 상태가 초기화될 수 있습니다.
화면은 저장소 인터페이스를 통해 데이터를 다루므로 이후 Supabase 저장소로 확장할 수 있습니다.
Vite 템플릿의 App.css와 예제 이미지 등은 미사용 상태로 보존되어 있습니다.

## 검사·빌드

```powershell
npm.cmd test
npm.cmd run lint
npm.cmd run build
npm.cmd run preview
```

- test: 핵심 데이터 규칙 자동 테스트 8개
- lint: 앱 소스·Vite 설정 검사
- build: TypeScript 검사 후 dist 폴더 생성
- preview: 빌드 결과를 로컬에서 확인. 터미널에 표시된 주소로 접속

빌드 결과의 index.html을 더블 클릭하는 대신 개발 서버 또는 preview를 사용하세요.
검증 내역과 남은 확인 항목은 `검증결과.md`에 있습니다.

## 다음 단계의 경계

Supabase 계정·프로젝트 연결, 실제 Gemini 호출, 비공개 사진 저장, RLS·구성원 권한,
서버 사용량 제한과 Cloudflare 배포는 별도 단계로 설계·검증합니다.
현재 화면의 데모 사용자와 그룹은 실제 인증·권한을 제공하지 않습니다.
Gemini 비밀키와 Supabase service role/secret 키는 브라우저 코드나 VITE_ 환경변수에 넣지 않습니다.
이 Phase 1에서 유료 서비스·결제·배포는 활성화하지 않았습니다.



## 사용자 API와 토큰 사용량

현재 버전은 모의 AI로 동작하므로 실제 API 토큰 사용량은 0입니다.
사용자 본인의 Gemini API를 연결하는 방식과 호출·토큰 절감 정책은 [사용자 API 정책](docs/사용자_API_정책.md)에 정리했습니다.
실제 API 연결과 사용량 제한은 아직 구현되지 않았습니다. 키를 코드나 GitHub에 올리지 마세요.

## 공개 저장소 구성

숫자 IP와 개인 Windows 경로를 소스와 안내에서 제거했습니다. 개발 서버의 주소는 실행 시 터미널에서 확인합니다.
설치 폴더, 빌드 결과, 로컬 캐시, 실제 환경변수 파일과 비밀키 파일은 Git에서 제외됩니다.
