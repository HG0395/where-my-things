# 사용자 Gemini API 정책

## 구현 상태

각 이용자가 로그인 후 자신의 키를 등록하는 코드를 구현했습니다. Supabase 프로젝트 연결과 함수 배포 전에는 데모만 동작합니다. 실제 서비스에서의 로그인·API 연동 검증은 아직 남아 있습니다.

## 키와 사진

- Gemini 키는 입력 중 화면 메모리에만 존재하며 서버 전송 후 입력창을 비웁니다. localStorage·코드·로그에 저장하지 않습니다.
- 서버는 로그인 토큰을 검증해 얻은 사용자 ID로만 키를 읽습니다. 요청 본문의 사용자 ID는 신뢰하지 않습니다.
- AES-256-GCM 암호화 키는 Supabase 서버 Secret에만 둡니다. 사용자 ID와 키 버전을 암호화 검증에 묶습니다. 운영자는 복호화할 수 있습니다.
- 키·사용량·캐시 테이블에는 RLS를 켜고 브라우저 역할의 직접 조회·수정과 RPC 실행 권한을 차단합니다.
- AI 전송에는 별도 동의가 필요합니다. 원본 대신 축소 사본을 Google Gemini로 보내며 앱 DB에 사진을 저장하지 않습니다. Google의 데이터 처리 정책도 확인하세요.
- 키 삭제·교체 시 해당 사용자 캐시를 지웁니다. 이미 전송한 요청은 취소하거나 회수할 수 없습니다.

## 호출·토큰 절감

| 항목      | 서버·화면 동작                                                                    |
| --------- | --------------------------------------------------------------------------------- |
| 호출 시점 | 분석 버튼과 전송 동의가 있을 때만 호출                                            |
| 사진      | 긴 변 1024px 이하, JPEG 품질 0.72, 최대 512KiB, 다시 인코딩해 메타데이터 제거     |
| 입력      | 사진 한 장과 짧은 한국어 지시만 전송. 물품 전체 목록·대화 기록 제외               |
| 출력      | 이름과 최대 3개 태그, JSON, 최대 출력 256토큰                                     |
| 모델      | gemini-2.5-flash-lite, thinkingBudget 0                                           |
| 캐시      | 사용자·사진·언어·모델·프롬프트 버전·키 버전별 24시간. 다른 사용자와 공유하지 않음 |
| 한도      | 한국 시간 날짜별 20회 시도, 요청 간격 20초, 처리 중 1건                           |
| 중복 방지 | DB 잠금으로 사용량 예약. 처리 예약 90초, 제공자 응답 대기 25초                    |
| 재시도    | Gemini 자동 재시도 없음. 실패 시 사용자가 직접 요청                               |

실패한 분석 시도도 일일 횟수에 포함됩니다. 캐시 적중은 횟수·Gemini 토큰을 추가하지 않습니다. 키를 바꿔도 사용 횟수가 초기화되지 않습니다. DB 기록을 원자적으로 예약하므로 여러 서버 인스턴스가 같은 계정 한도를 공유합니다. 실제 배포 환경의 부하 검증은 별도입니다.

토큰 표시는 제공자 응답의 입력·출력 토큰 수입니다. 확정 요금이나 비용 상한을 뜻하지 않습니다. Google 프로젝트에서 다른 앱이 같은 키를 사용한 양까지 이 앱이 제한하지는 못합니다. 무료 한도·모델 이용 가능 여부·데이터 처리 조건은 운영 시점에 확인해야 하며, 앱은 결제를 자동 활성화하지 않습니다.

완료 결과 캐시는 24시간 유효합니다. 만료 작업과 30일이 지난 사용량 기록은 해당 사용자의 다음 분석 요청에서 정리합니다. 키 삭제 시 캐시는 즉시 삭제하지만 사용량 기록은 유지합니다. 계정 삭제 시 관련 테이블 행은 함께 삭제됩니다.
